# Wave 2: Gacha — Security, Storage, Stats, Rendering Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. You implement ONE lane (the one named in your brief). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the gacha feature safe (nobody can touch another user's data or poison shared data), correct (statistics), and fast (no full-log parse, no 7 MB rewrite, no redraw of cards already drawn).

**Architecture:** Four lanes in parallel, each in its own worktree cut from `opt/2026-11`, each owning a fixed set of the files produced by the Wave 1 split (`src/features/gacha/**`). Lanes do not call each other's new code; the two places where they must meet are wired by the main session after merge (listed under "Main-session wiring").

**Tech Stack:** TypeScript 5.9 (CommonJS), discord.js 14, better-sqlite3 key/value store shared by 5 cluster processes, @napi-rs/canvas. Tests: `node:assert/strict` scripts `*.test.ts`, run with `yarn test [substring]`.

**Spec:** `docs/superpowers/specs/2026-11-19-bot-optimization-design.md` section 6 "第 2 波" (G1–G4) and section 7. Where this plan and the spec differ, this plan wins (it was written after the split and after measuring production).

## Production facts (measured 2026-11-19)

- `GACHA_LOG_*`: ~3,400 rows, ~685 MB total, largest row 2.6 MB of JSON. Every stats view parses the whole row today.
- `GACHA_LEADERBOARD_ENTRIES`: one 6.9 MB row, read-modified-rewritten on every stats view.
- 5 cluster processes share the SQLite file; all DB calls are synchronous and block that process's event loop.

## Global Constraints

- Work only inside your worktree, on your branch. Commit after each task. Never push. Never start the bot. Never read `.env`. Never call real game/SKPort APIs.
- **Edit only the files your lane owns.** Anything else → "Requests to main session" in your report. Do not edit `scripts/known-failing-tests.json`; if you fix one of the four known-failing tests that belongs to your lane, say so in the report.
- No new npm dependencies.
- User-visible strings go through `tr()`; add keys to both `src/assets/languages/en.ts` and `tw.ts` only inside your lane's `// --- Gx ---` block. tw is Traditional Chinese (Taiwan wording).
- Shared rows: read-modify-write only through `db.update` / `db.transaction`. Available helpers: `setWithTtl`, `getFresh`, `deleteByPrefix`, `update`, `withKeyLock`, `transaction`, `findByPrefix` family, plus what L4 added (read `src/utils/Database.ts`).
- Run-once / periodic jobs: `client.startup.onPrimary(name, fn)` / `client.startup.every(name, ms, fn)`.
- Data migrations: idempotent, from a startup hook, **never delete or rewrite the old data** in this wave, and bounded per run so the event loop is never blocked for more than ~50 ms at a time (process in batches, yield with `setImmediate` between batches).
- Every interaction must be acknowledged within 3 s: `deferReply` / `deferUpdate` before any network call or large-row read.
- Card appearance must not change except where a task says so. `yarn test renderBaseline` compares 15 rendered cards against stored hashes; if a task intentionally changes a card, regenerate the baseline in the same commit and name the changed images and the reason in the commit message. An unexplained hash change is a bug.
- UI: icon + a few words rather than plain text; lists get paging; every view can be closed.
- Keep CRLF line endings as found; do not reformat untouched lines.
- Each task: failing test first, implement, `yarn test` exit 0, `npx tsc --noEmit` clean, commit with trailer `Co-Authored-By: Claude Fable 5.2 <noreply@anthropic.com>`.
- Put decisions in small pure exported functions that take plain data, and test those.

## Review Focus

1. A user acting on a UID that is not theirs: every write path (clear, migrate, recover, load-into-UID) and every component click must verify ownership server-side; a customId carrying a UID proves nothing. (G1, G3)
2. A pasted import URL pointing at a host that is not the official API must be refused before any request is made, including after redirects. (G1)
3. Logs written by the old code (no `updatedAt`, no reset markers, legacy `GACHA_LOG_<uid>` key forms, guest keys) must keep working and produce the same statistics as before unless a task says the old number was wrong. (G2, G3)
4. Two clusters handling the same user at once (load on one, view on another) must not lose records or leave a cache that never refreshes. (G2, G3)
5. A cache must never serve user A's card or stats to user B, and must be bounded in memory. (G3, G4)

Each lane adds a test for every line above that names it.

## Main-session wiring (do NOT do these in a lane; just provide the function)

- **Incremental import:** G1 adds an optional stop condition to the fetch in `gachaApi.ts`; the call sites in `gachaStore.ts` (G2's file) are wired by the main session after merge.
- **Guild scope:** G2 exports `noteLeaderboardGuild(db, uid, guildId)`; calls from `command/load.ts` and `command/view.ts` are added by the main session.
- **Leaderboard on view:** G3 removes the `updateLeaderboard` call from `command/view.ts`; G2 makes the store update the leaderboard after import/clear/migrate. Both are needed; each lane does its own half.

## Lane G1 — Gacha security & import API

**Worktree/branch:** `C:\wt\endfield-g1`, `opt/g1-gacha-security`

**Owns:** `src/features/gacha/gachaApi.ts`, `gachaFingerprint.ts`, `command/load.ts`, `command/maintenance.ts`, `command/components.ts`, `command/accounts.ts`, `command/autoLoad.ts`, `src/commands/general/gacha.ts`, tests `src/utils/gachaLoadAck.test.ts`, `gachaGuestLookup.test.ts`, `gachaRerun*.test.ts`.

- [ ] **Task 1: Ownership.** Pure `resolveOwnedGachaUid(requestedUid, ownedUids): { ok: true; uid } | { ok: false; reason }` and `listOwnedGachaUids(accounts, userId)` (linked-account role UIDs in every key form the store uses, plus that user's own guest keys). `log clear` and its confirm/cancel, recover and migrate handlers accept only owned UIDs. `findLinkedAccount` must not fall back to "first usable account" when no account owns the UID (that can import a log into the wrong UID): return null and tell the user. Tests: someone else's UID; a UID in another key form of an owned account; guest key of another user; no accounts.
- [ ] **Task 2: Component invoker check.** In `components.ts`, every gacha button/select/modal verifies the clicker. Stateful confirmations (clear, fingerprint keep/switch, migrate, recover): only the invoker; others get an ephemeral localized notice. View-type components (paging, pool/type selects, leaderboard selects) on a non-ephemeral message: only the invoker may change the message; others get the ephemeral notice. Decide the invoker from `interaction.message.interaction?.user.id` / `interactionMetadata` with a fallback of embedding the invoker id in new customIds (old messages without it: allow only if the message's interaction user matches, otherwise refuse). Pure `mayOperateGachaComponent(...)` with tests.
- [ ] **Task 3: Import URL allow-list.** Pure `validateGachaImportUrl(input): { ok: true; apiBase: string; token: … } | { ok: false; reason }`. Derive the allowed hosts from what `fetchRawGachaFromUrl` already targets when given a bare token (the gryphline / hypergryph API hosts in the code) — exact hosts only, HTTPS only, no userinfo, default port. A pasted URL on any other host is refused with a localized message before any request. Requests use `maxRedirects: 0`. Tests: official URL, bare token, look-alike host (`ef-webview.gryphline.com.evil.com`), userinfo trick, `http:`, IP literal.
- [ ] **Task 4: Timeouts and honest partial imports.** Every axios call in `gachaApi.ts`: `timeout: 15000`. A pool list that fails, or a non-zero API code mid-pool, no longer silently `break`s/skips: the fetch result gains `incomplete: Array<{ poolType; poolId?; reason }>`, and `load.ts` tells the user which parts are missing (and does not present the import as complete).
- [ ] **Task 5: Incremental fetch option.** `fetchRawGachaFromUrl` (and the linked-account path) accept an optional `stopAt?: { character?: (seqId: string) => boolean; weapon?: (seqId: string) => boolean }`; when the predicate returns true for a record, stop paging that pool after finishing the current page. Default (no option) = today's behaviour. Unit-test with a fake page source. Do not edit `gachaStore.ts`.
- [ ] **Task 6: Pending rows.** `PENDING_GACHA_URL_*` and `PENDING_GACHA_FINGERPRINT_*`: store via `setWithTtl` (15 min), value encrypted with `cryptoUtils.encrypt`, read via `getFresh`; legacy rows without TTL are ignored and deleted when encountered. Acknowledge the modal-submit and `log_load_select_target` paths before any account/network lookup.
- [ ] **Task 7:** Fix `gachaLoadAck.test.ts` if it is failing only because its fake `db` lacks newer methods. **Report.**

## Lane G2 — Leaderboard & storage

**Worktree/branch:** `C:\wt\endfield-g2`, `opt/g2-gacha-storage`

**Owns:** `src/features/gacha/gachaStore.ts`, `gachaLeaderboard.ts`, `gachaTypes.ts`, `command/leaderboard.ts`, `src/utils/gachaLeaderboardCanvasUtils.ts`, tests `src/utils/gachaLogUtils.test.ts`, `gachaNonDrawEvents.test.ts`.

- [ ] **Task 1: One row per UID.** Leaderboard entries move to `GACHA_LB.<uid>` (value = the existing entry shape + `guilds: string[]` + `updatedAt`). Startup migration from the `GACHA_LEADERBOARD_ENTRIES` blob: idempotent, batched (≤ 500 entries per batch, `setImmediate` between), never overwrites an existing `GACHA_LB.*` row, leaves the blob untouched, sets a done-marker. Readers use `findByPrefix("GACHA_LB.")`; nothing reads or writes the blob afterwards. `deduplicateLeaderboardAliases` semantics preserved (test with the alias cases it handles today).
- [ ] **Task 2: Update on write, not on view.** `gachaStore` updates the UID's leaderboard row at the end of a successful import/merge, on clear (remove or recompute) and on migrate — inside the same transaction as the log write where possible. Every write to a `GACHA_LOG_*` row also sets `info.updatedAt = Date.now()`. Export `noteLeaderboardGuild(db, uid, guildId): void` (adds the guild id, max 50 per entry, `db.update`).
- [ ] **Task 3: Correct luck.** One pure `computeLeaderboardMetrics(stats)`; six-star rate = non-free 6★ / non-free pulls (same definition as the stats card). Luck-type sorts require ≥ 100 non-free pulls in the ranked category (constant `MIN_PULLS_FOR_LUCK_RANK = 100`); total-pull sorts have no minimum. Tests incl. 1 pull / one 6★ (unranked), free 6★ present, exactly 100.
- [ ] **Task 4: Paging and scope.** Leaderboard card: 10 per page with ◀ ▶ page buttons and a "my rank" jump button; a scope select 🌐 global / 🏠 this server (server = entries whose `guilds` include the current guild; in DMs only global). When the server list is empty show a one-line localized hint that the list fills as members load or view their records here. The invoker's own row is highlighted and shown beneath the page if not on it. Rendering changes to the leaderboard card are intentional: regenerate the two leaderboard baselines.
- [ ] **Task 5: Keep reset markers.** `charPityResetSeqId` / `weaponPityResetSeqId` survive a re-import: carry over from the existing log unless the new merge proves the gap is closed (define and test the rule in a pure function `mergePityResetMarkers(existingInfo, mergedRecords)`).
- [ ] **Task 6: Atomic shared rows.** `GACHA_POOL_NAMES` and the `SIM_POOL_RECORDS.*` writes go through `db.update`/`transaction`; the log merge itself is read-merge-write inside one transaction keyed on the UID so a concurrent load cannot drop records (the network fetch happens before, outside the transaction; the merge re-reads the stored log inside it).
- [ ] **Task 7:** Investigate `gachaNonDrawEvents.test.ts` (fails with `Cannot read properties of undefined (reading 'total')`): fix the test or the code, whichever is wrong, and say which. **Report**, incl. how long the blob migration takes on a synthetic 7 MB blob.

## Lane G3 — Stats engine, stats cache & the view command

**Worktree/branch:** `C:\wt\endfield-g3`, `opt/g3-gacha-stats`

**Owns:** `src/features/gacha/gachaStatsEngine.ts`, new `src/features/gacha/gachaStatsCache.ts`, `command/view.ts`, `command/list.ts`, `command/autocomplete.ts`, `command/builder.ts`, `command/context.ts`, `src/utils/gachaPoolUtils.ts`, `src/utils/Database.ts` (additive only), tests `src/utils/gachaAutocomplete*.test.ts`, `gachaWinRate.test.ts`.

- [ ] **Task 1: Version token without parsing.** `Database.getRowToken(key, jsonPath?): { length: number; field: string | null } | null` — one SQL `SELECT length(json), json_extract(json, ?)`; no JS-side JSON parse. `gachaStatsCache.ts`: `getCachedGachaStats(db, logKey, compute)`; cache row `GACHA_STATS.<logKey>` = `{ engine: ENGINE_VERSION, token: "<length>:<info.updatedAt|''>", stats }`; on hit return `stats` without reading the log row; on miss read + compute + store. `ENGINE_VERSION` constant lives in `gachaStatsEngine.ts` (start at 1; bump whenever the algorithm changes — this wave's Task 3 bumps it). Tests: hit does not call `compute`; a changed log length or `updatedAt` misses; engine bump misses; two different log keys never share an entry; a log row deleted → cache row deleted on next access.
- [ ] **Task 2: View reads the cache and writes nothing.** `showGachaStats` and paging/select re-renders obtain stats through the cache. Remove from the view path: the `updateLeaderboard` call, the nickname back-fill write, and per-view `ensureAccountBinding` (use the cached role mapping that autocomplete already uses; refresh bindings only on a miss). A view of an existing log performs zero DB writes on a cache hit — assert this in a test with a counting fake DB.
- [ ] **Task 3: Correct "featured".** A 6★ whose pool metadata is unknown is no longer assumed featured: resolve from pool metadata → name match → the standard list → otherwise `unknown`; `unknown` counts in neither numerator nor denominator of the win rate and the stats expose `unknownFeaturedCount` (the card shows nothing new in this lane). Bump `ENGINE_VERSION`. Table tests incl. a new permanent character absent from the hardcoded list.
- [ ] **Task 4: Read access.** `view user:X account:Y`: `Y` must be one of X's own UIDs (X defaults to the invoker); otherwise a localized refusal. Viewing another user's log remains possible only through `user:` (as today). Autocomplete for `account` lists only the invoker's (or selected user's) UIDs. Fix `gachaAutocomplete.test.ts` if it fails only for its stale fake `db`.
- [ ] **Task 5: More than 24 pools.** Pool select: newest 23 + a "◀ older / newer ▶" paging option pair, so every pool is reachable. Pure `pagePoolOptions(pools, page)` with tests (0, 1, 24, 25, 60 pools).
- [ ] **Task 6: `/gacha list` shows the weapon banner** it already fetches (same visual language as the character banner block); remove the dead `hasData`.
- [ ] **Task 7: Bench + report.** `scripts/bench-gacha-stats.ts`: build a synthetic log of ~2 MB JSON (reuse the generator in `scripts/render-gacha-fixture.ts` by import, do not edit it), measure median of 20 runs for: cold stats (parse + compute), cached stats, and DB writes per view; print before/after (run "before" on commit `opt/2026-11` via `git stash`-free means: the script takes a `--no-cache` flag that bypasses the cache to reproduce the old path). Put the numbers in the report.

## Lane G4 — Rendering performance

**Worktree/branch:** `C:\wt\endfield-g4`, `opt/g4-gacha-render`

**Owns:** `src/features/gacha/iconLoader.ts`, `src/features/gacha/statsCanvas/**`, `src/utils/gachaCanvasUtils.ts`, `src/utils/gachaSimulatorUtils.ts`, `src/features/gacha/command/simulate.ts`, `src/utils/canvasUtils.ts`, tests `src/utils/gachaCanvasUtils.test.ts`, `src/features/gacha/renderBaseline.test.ts` + its fixture JSON, `scripts/render-gacha-fixture.ts`.

- [ ] **Task 1: Decoded-image cache.** One shared bounded LRU for decoded images (by count and by estimated bytes `width*height*4`, cap 256 MB, constant) used by `loadGachaIconImage`, the backgrounds (`bg-rb.png` etc.) and `canvasUtils` `loadLocalImage`/`fetchImage` (replacing the unbounded `imageCache` Map there). Local icon lookup: build an index of the icon directories once (lazily, refreshed at most every 10 min) instead of probing up to 12 candidate paths with `existsSync` per icon per render. Tests: eviction order, byte cap, index finds the same file the old probing order would have chosen (table of candidate lists).
- [ ] **Task 2: Rendered-card cache.** In the `drawGachaStats` wrapper: key = sha1 of a stable serialization of all inputs that affect pixels (stats, view params, language, user display fields) → cached encoded buffer; LRU, cap 64 MB / 200 entries, TTL 10 min. A hit returns the stored buffer without touching canvas. Tests: identical inputs → same buffer object, any differing field → miss, cap respected, entries for different UIDs never collide (Review Focus 5). The baseline test must still pass with the cache enabled and with it bypassed.
- [ ] **Task 3: No network in the draw path.** Remove the untimed per-render `fetch` in `statsCanvas/drawGachaStats.ts`; the pool data it wanted comes from `getPoolMetadata` (already called) — if a field is only available from that fetch, list it under "Requests to main session" rather than keeping the fetch. Any remaining image download in a draw path has an 8 s timeout and a placeholder on failure. Simulator: character images load in parallel (`Promise.all`) with the same timeout.
- [ ] **Task 4: `canvasUtils` image safety** (requested by the web-security lane): `fetchImage` only downloads from hosts accepted by `validateProxyUrl` in `src/web/imageProxy.ts` (import it; own-asset links are already handled by `resolveOwnAssetRel`); `loadLocalImage` and `drawProfileBackground` refuse a path that resolves outside the assets dir. Tests for traversal and a non-allow-listed host. A refused image renders as "missing", never throws out of the card.
- [ ] **Task 5: Icons without code changes.** When an operator/weapon is missing from the hardcoded icon tables, fall back to the icon URL in the pool/wiki metadata the bot already stores (find where `getPoolMetadata` / the wiki pool endpoints expose it; if nothing stored carries an icon URL, say so and stop — do not invent an endpoint). Fix `gachaCanvasUtils.test.ts` (its expected candidate list is out of date) to match the intended order.
- [ ] **Task 6: Overview totals and strings.** (a) Write a test that shows whether Joint-pool pulls are missing from the limited-character overview totals (`statsCanvas/overview.ts`, the `gid === "SpecialShared"` sum); if they are, include them and regenerate the affected baselines. (b) Hard-coded Chinese in the detail card ("總計", "加急", "抽") → `tr()` keys (tw text identical, so tw baselines unchanged; en baselines change — regenerate and say so). (c) The slash `simulate` reply and the `sim_pull` button show different text for the same state: make both use one function.
- [ ] **Task 7: Bench + report.** `scripts/bench-gacha-render.ts`: median of 10 for overview and one detail page, cold process vs warm image cache vs card-cache hit, before/after (a `--no-cache` flag reproduces the old path). Numbers in the report, plus peak RSS.
