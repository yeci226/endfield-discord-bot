# Wave 1: Five Parallel Lanes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. You implement ONE lane (the one named in your brief). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Split the gacha code for parallel work, close the web/credential holes, make daily sign-in, news and reminders actually work, remove wasted work in the core, and ship two new commands.

**Architecture:** Five lanes, each in its own git worktree and branch cut from `opt/2026-11` (which already contains Wave 0). Each lane owns a fixed set of files; lanes meet only through the interfaces listed below. The main session reviews and merges.

**Tech Stack:** TypeScript 5.9 (CommonJS), discord.js 14, discord-hybrid-sharding (5 clusters in production), better-sqlite3 key/value store, express 5, @napi-rs/canvas. Tests: `node:assert/strict` scripts `*.test.ts`, run with `yarn test [substring]`.

**Spec:** `docs/superpowers/specs/2026-11-19-bot-optimization-design.md` — section 6 "第 1 波" lists each lane's behaviour requirements with source locations. **The spec's bullet list for your lane is your requirement list; this plan adds the decisions the spec leaves open.** Read both.

## Global Constraints

- Work only inside your worktree, on your branch. Commit after each task. Never push. Never start the bot. Never read `.env` or print stored credentials.
- **Edit only the files your lane owns** (listed per lane). If you need a change in any other file, do not make it: describe it under "Requests to main session" in your report.
- No new npm dependencies.
- All user-visible strings go through `tr()`; add keys to **both** `src/assets/languages/en.ts` and `tw.ts`, **only inside your lane's `// --- Lx ---` block at the end of the file**. Do not move or edit existing keys. tw is Traditional Chinese (Taiwan wording).
- Database: use the existing `CustomDatabase` API plus the Wave 0 helpers (`setWithTtl`, `getFresh`, `deleteByPrefix`, `update`, `withKeyLock`). Do not edit `src/utils/Database.ts` unless your lane owns it.
- Run-once / periodic jobs: register with `client.startup.onPrimary(name, fn)` / `client.startup.every(name, ms, fn)`. Do not edit `src/index.ts` or `src/events/ready.ts` unless your lane owns them.
- Data migrations: idempotent, run from a startup hook, and **never delete the old data** in this wave.
- No card's appearance changes unless your lane's spec bullet says so.
- UI: prefer icon + a few words over plain text; lists get paging or filtering; every view can be left/closed.
- Keep each file's line endings; do not reformat untouched lines.
- Each task: write the failing test first, implement, `yarn test` exit 0, `npx tsc --noEmit` clean, commit. Commit trailer: `Co-Authored-By: Claude Fable 5.2 <noreply@anthropic.com>`.
- Pure logic must be testable without Discord or network: put decisions in small exported functions that take plain data, and test those.

## Review Focus

1. A Discord interaction must be acknowledged within 3 s: anything that may hit the network or a large DB row must `deferReply`/`deferUpdate` first. (all lanes)
2. Five processes share one SQLite file: any read-modify-write of a shared row must go through `db.update` or `db.transaction`, not `get` then `set`. (L2, L3, L4)
3. Legacy data shapes already in production must keep working: plaintext credentials, `monitorConfig` rules, the `news_subscriptions` array, accounts with `roles: []`. (L2, L3, L4)
4. A user with zero linked accounts, or with only an Arknights (gameId 1) binding, must get a clear localized message, not a crash or an empty card. (L3, L5)
5. Outbound requests to user-influenced URLs must be allow-listed and time-bounded. (L2)

Each lane adds a test for every line above that names it.

## Lane L2 — Web & credential security

**Worktree/branch:** `C:\wt\endfield-l2`, `opt/l2-web-security`

**Owns:** `src/web/**`, `src/utils/cryptoUtils.ts`, `src/events/messageCreate.ts`, `src/commands/account/login.ts`, `src/commands/general/profile.ts`, `src/utils/profileView.ts`.

Decisions beyond the spec:
- Image proxy allow-list (exact host or subdomain of): `skport.com`, `gryphline.com`, `hypergryph.com`, `hycdn.cn`, `discordapp.com`, `discordapp.net`. First grep the repo for every URL the editor/cards actually proxy and add any missing first-party host; list what you added. HTTPS only. Reject IP-literal hosts. 8 s timeout, 8 MB cap (abort the stream when exceeded), response `content-type` must start with `image/` and not be `image/svg+xml`; file extension derived from content-type only. Redirects: follow at most 3, re-checking the allow-list each hop. Cache dir capped at 300 MB / 5000 files, evict oldest by mtime from a `client.startup.every` hook (hourly).
- `/assets` static serving: set `X-Content-Type-Options: nosniff`; never serve `.html`/`.svg`/`.js` from `assets/cache`.
- Tokens: `crypto.randomBytes(24).toString("base64url")`. Request logger logs the path with any token segment replaced by `:token`.
- `profile_edit_token:*` rows: store with an `expiresAt`; hourly hook deletes expired ones. `dataCache`: max 200 entries, evict on token expiry.
- `encrypt()` throws on failure. At module load, if `NODE_ENV === "production"` and `ENCRYPTION_KEY` is missing or not the required length → throw (the bot then refuses to start). `decrypt()` keeps returning legacy plaintext input unchanged, but must throw on a value that has the encrypted format and fails authentication (do not hand back garbage).
- Owner debug command: output `maskSecret()` values only.
- CORS: allowed origins from env `WEB_ALLOWED_ORIGINS` (comma-separated); default = same-origin only. In-memory rate limit: 30 req/min per IP on `/callback` and `/api/preview/*`, 120 req/min on the proxy (use `X-Forwarded-For` first hop only when the socket peer is loopback — production sits behind cloudflared). Preview body limit 2 MB; errors return a generic message.
- Captcha across clusters: `/callback` validates that the session exists, then `db.setWithTtl("captcha_result:<sid>", payload, 15 * 60_000)`. `VerificationClient.waitForResult(sid, timeoutMs)` polls `db.getFresh` every 1000 ms, deletes the row when read, rejects on timeout; no EventEmitter state left behind. `/login` uses it.

- [ ] **Task 1:** `cryptoUtils` (throwing encrypt, module-load check, strict decrypt, `maskSecret`) + tests incl. legacy plaintext passthrough and tampered ciphertext.
- [ ] **Task 2:** Image proxy: extract `validateProxyUrl(url): { ok: true; url: URL } | { ok: false; reason: string }` and `extensionForContentType(ct): string | null` as pure functions with tests (localhost, 127.0.0.1, `[::1]`, `10.0.0.1`, `http://`, userinfo `https://skport.com@evil.com/`, `evil-skport.com`, `skport.com.evil.com`, an allowed subdomain, svg, html). Then wire them in with timeout/size cap/redirect handling and cache eviction.
- [ ] **Task 3:** Tokens, log masking, token-row expiry, `dataCache` bound, CORS, rate limiter (pure `createRateLimiter({ limit, windowMs })` with tests), preview limits.
- [ ] **Task 4:** Cross-cluster captcha (`waitForResult` tested against a temp DB: result arrives late → resolves; never arrives → rejects; row is removed after read).
- [ ] **Task 5:** Owner debug command masking.
- [ ] **Task 6: Report** incl. any first-party host added to the allow-list and every place the editor page (`public/index.html`) calls the proxy.

## Lane L4 — News, reminders & core efficiency

**Worktree/branch:** `C:\wt\endfield-l4`, `opt/l4-core`

**Owns:** `src/services/SkportNewsService.ts`, `src/services/MonitorService.ts`, `src/commands/general/news.ts`, `src/commands/general/reminder.ts`, `src/commands/general/language.ts`, `src/commands/admin/**`, `src/utils/reminders.ts`, `src/utils/reminderWizard.ts`, `src/utils/reminderWizardSessions.ts`, `src/utils/cardNotification.ts`, `src/events/**` except `messageCreate.ts`, `src/cluster.ts`, `src/index.ts`, `src/structures/Client.ts`, `src/handlers/**`, `src/utils/Database.ts`, `src/utils/shared.ts`, `src/utils/sharedCompat.ts`, `src/optimizations/**`, `src/commands/general/monitor.ts.disabled`, new `src/utils/rateLimit.ts`, new `src/utils/commandRegistry.ts`.

Decisions beyond the spec:
- News subscriptions: one row per subscription, key `news_sub.<guildId or "DM">.<channelId or userId>`, value `{ guildId, channelId, userId?, lang?, failCount, addedAt }`. Startup migration copies the `news_subscriptions` array into rows (skip rows that exist) and leaves the array in place; the service reads rows only. Dispatch: per item per subscription key `news_dispatch.<itemId>.<subKey>` is written **after** a successful send. Failure: permanent Discord codes (10003, 10004, 10007, 50001, 50007, 50013) → `failCount += 1`, remove the subscription at 3; other errors → retry next poll (max 5 attempts per item, tracked in the dispatch row). Poll takes every item newer than the oldest undelivered one, capped at 10 per poll. Hourly hook deletes `news_dispatch.*` rows older than 90 days — add `createdAt` to new rows; legacy rows without it are deleted only if their item is no longer in the feed.
- DM subscriptions: delivered by `client.users.send` from the primary cluster.
- Reminders: one `card/detail` fetch per account per poll (memoize by account inside one poll pass); `retryAt = min(1h, leadTime / 2, floor 5 min)`; startup migration converts legacy `monitorConfig` entries to `reminder.v2.*` rules (idempotent, legacy kept).
- `/reminder` becomes two subcommands: `setup` (the existing wizard) and `list`. `list` shows the user's rules as a paged select: icon for type (sanity / daily), account + role name, delivery target, next fire time; buttons: pause/resume, delete, close. Only the invoking user can operate it.
- Command registration: `src/utils/commandRegistry.ts` exports `computeCommandsHash(commandsJson: unknown[]): string` (sort by name, stable-stringify, sha256). Only cluster 0 registers, only when the hash differs from DB `commands_hash`; write the hash after a successful `rest.put`.
- Presence: only cluster 0 computes the guild total (one `broadcastEval`) every 60 s and pushes the same presence to all clusters with a second `broadcastEval`; skip when the number has not changed.
- `cluster.ts`: one interval per cluster id (clear on respawn). `Client.start()` awaits `login` and logs success only after it resolves; a login failure exits non-zero.
- `uncaughtException`: log, send webhook (throttled: max 1 per 30 s per error message, null-safe), then `process.exit(1)` after 1 s. `unhandledRejection`: log + throttled webhook, do not exit.
- `/language`: export `invalidateLocaleCache(userId)` from `interactionCreate.ts` and call it.
- Interaction errors (button, select, modal, autocomplete): always answer the user with a localized generic error (ephemeral), using reply / followUp / editReply depending on state; autocomplete answers `[]`.
- Rate limit: `src/utils/rateLimit.ts` `createRateLimiter({ limit, windowMs, maxKeys })` (sliding window, evicts idle keys). Apply in `interactionCreate`: 20 interactions / 10 s per user; over the limit → ephemeral localized notice, autocomplete → `[]`.
- `Database.ts`: `findByPrefix`, `findKeysByPrefix`, `findFieldByPrefix`, `findIdsByPrefix` switch from `LIKE` to the `ID >= ? AND ID < ?` range form (same results for every prefix currently used in the codebase — grep all call sites and confirm none relied on `_`/`%` wildcards; list them in the report).
- `move-daily-notify`: per-row `db.update`, no load-all-then-rewrite.
- Delete: `src/optimizations/**`, `src/utils/sharedCompat.ts`, `monitor.ts.disabled`, the `OptimizationManager` wiring in `index.ts`. Before deleting each, grep to prove nothing imports it.
